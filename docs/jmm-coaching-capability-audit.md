# JMM coaching capability audit and implementation brief

## Verdict

JMM has an implemented planning and daily review engine, a dedicated conversational interface, a human coach workspace, and a race scenario calculator. It is not yet proven as a fully autonomous high-performance coach. Use a reviewed plan and staged edits. Treat the race output as a scenario until accuracy is established against recorded outcomes.

## Copy-ready implementation prompt

> Start from current main. Inventory the authenticated flows and reuse the validated planning, calendar, check-in, Koach, metrics and race scenario services. Record the release SHA and whether each workflow is source-implemented, exercised locally, or verified live. Keep the separate coaching and metrics drafts reviewable. Do not merge or release without approval.
>
> Make one complete journey work first: a new triathlete selects a sport and availability, receives a provisional week, opens Today and Calendar, records one actual and one unplanned workout, receives a documented daily review, previews a cycle for a custom-distance race, and reviews the race execution card with the assigned coach. Repeat the core acceptance tests for swimming, cycling, running, track sprint, and HYROX; explicitly label strength and other legacy sport coverage. Include a no-race/no-device athlete, a well-trained athlete, and an athlete reporting new pain. Keep actual history when replacing future plans.
>
> Keep the calendar centered on the next seven days and a month overview. Distinguish planned, adapted, logged and review states. Show a workout's purpose, complete warm-up/main/cool-down and exact endpoints. Show targets only for the sport and step where a dated applicable reference exists. Use preferred units, show nutrition/preparation separately, and keep report/move/Koach actions near the day. Preserve a planned workout beside an unplanned activity until a verified link or reviewed change is made.
>
> Connect Koach to protected read tools for the current athlete's profile, benchmark dates/sources, history, calendar, races, availability, equipment and eligible biometrics. Return protected results as local cards. Keep external dialogue optional; do not send restricted device data, derived summaries or protected card contents to the model. Ask one consequential missing question at a time. Require reviewed proposals, revision checks and save receipts for consequential actions. Validate numbers and units, reject ambiguous voice transcripts, and do not diagnose injury.
>
> Build the Coaching Desk around a single assigned athlete: planned vs actual time by sport, dated performance references, load coverage and gaps, recovery and reported symptoms. Add documented coach overrides with rationale, previous value and receipt. Keep human and automated actions distinguishable. Verify no cross-athlete reads/writes, no stale access after revocation, and no unsafe fallbacks.
>
> For event execution, bind inputs to the actual race, date, course and distance. Show swim pace and conditions, bike watts/speed/kJ under explicit course assumptions, and run pace plus observed HR or same-device running watts only when justified. Use transitions and fueling practice where reported. Show missing evidence and separate a scenario range from a validated prediction. Freeze pre-event predictions, compare against official outcomes on held-out athletes/events, and report error and coverage before claiming accuracy.
>
> Deliver small draft PRs with fixtures, screenshots and passed/failed/blocked results. Run typecheck, lint, suite, production build and authenticated browser acceptance with synthetic data; verify production provider behavior only with scoped authorization. Do not activate automatic training increases or weaken provider permissions.
