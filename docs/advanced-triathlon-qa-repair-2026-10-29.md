## State, schema and migration

Reuse existing protected `AthleteProfile`, `Workout.prescription`, check-in records and profile audit transactions; do not create a parallel coaching system. Canonical sessions remain schema version 2, with a typed blocked-review requirement and target reference metadata. Nutrition adds `session-nutrition-v1`, session ID and canonical source revision. New advanced/pro half-distance weeks identify `triathlon-foundation-v2`; old saved cycles are retained and flagged for review, not silently rewritten.

No database migration is required. Explicit reported FTP/run/CSS records use reserved labels, original canonical units and actual dates in the existing bounded personal-record list. They are displayed as results/reference records, not relabeled as race PBs or tests. Dating one sport does not renew another sport. Existing list-size limits still apply. Profile audit history and optimistic revision checks remain in force. Revoking/changing a reference changes the canonical revision; unreviewed or expired values cannot create numerical targets.

## Verification and release gates

Automated PR review identified and this change corrects selected-session null nutrition falling back to another meal, CSS-resolved easy swims being classified as unknown load, and older matching tests taking precedence over newer explicit reports. Target and cycle provenance now select the newest matching observation, retaining verified evidence on the same local date. Faster/unknown swim targets still retain demanding/unknown guards. The HTTP fixture explicitly substitutes Mon–Sat only on Mondays; deterministic persona tests retain the original Tue–Sun scenario. Browser acceptance also exercises the existing pool editor, not a replacement: saved structures lacking optional time estimates remain in editable JSON instead of becoming trapped in a simple form that requires invented estimates.

New deterministic persona tests use the supplied thresholds, imperial conversions, 720-minute history, 300-minute ceiling, optional Wednesday agreement and original A/B/C race dates. They check dated/undated/stale/future references, sport frequencies, daily sums, event protection, numerical targets, swim structure, FIT decoding, sodium/protein, body saves and intent handling.

New isolated HTTP/PostgreSQL/mobile acceptance creates disposable synthetic accounts, saves/reloads the profile and 24-week cycle, compares Check-In/Today/reload revisions and nutrition, checks actionable missing-pool failure, supplies an explicit synthetic pool revision and decodes its downloaded FIT. Explicit fixture structure is not a claim that a real athlete or coach approved a pool session. It also tests foreign-athlete download rejection and saves screenshots. No real OAuth connection, email, Telegram, external AI, watch transfer or device receipt is used.

Final exact-head results belong in the PR checks and evidence artifact. Local compile/test/build results do not substitute for browser acceptance. Known open release gates: a complete coach-reviewed advanced triathlon program (including bricks/open-water rehearsal, configurable reviewed distribution and taper), nutrition/supplement editorial approval, the remaining legacy localization/accessibility pass, full matched-turnaround/dietary persona review, real authorized provider/device receipts, and production authorization. This PR is a correctness and safety repair, not certification of all 16 proposed acceptance requirements or autonomous advanced coaching.
